# Gentleman 韩漫登录态改造

## 结论

Gentleman 的韩漫模块现在必须登录后访问。这里的“下载”是 `smanga-get` 通过浏览器访问、解析并抓取漫画内容，不是调用网站自带的下载功能。

当前 Gentleman 订阅全部是韩漫，因此不修改订阅格式，也不迁移订阅数据。认证逻辑只接入 Gentleman 服务，不影响 Toomics、Bilibili、OmegaScans 等其他漫画模块。

## 站点反馈

未登录访问以下页面：

```text
https://www.wnacg.ru/albums-index-cate-38.html
```

页面返回“您要訪問的漫畫不存在！”并显示“點擊這裡登錄”。该页面作为登录探针，比检查 Cookie 文件是否非空或把搜索结果为空视为未登录更可靠。

探针使用三态结果：

- `authenticated`：页面包含分类列表结构 `gallary_wrap` 和作品详情链接；
- `login-required`：同时命中“不存在”和“登录”提示；
- `unexpected`：Cloudflare、安全验证、限流或无法识别的页面，按技术故障处理，不误报 Cookie 失效。

## 运行流程

1. Gentleman 任务启动共享浏览器，并从 `gentleman.cookieFile` 加载 Cookie；
2. 在解析订阅搜索页之前访问韩漫分类探针；
3. 登录有效时保存站点可能续期的 Cookie，然后继续原有爬取流程；
4. 未登录时关闭旧 Gentleman 浏览器，将当前任务放回队首并标记为 `paused`；
5. 队列停止，后续任务保持原顺序；
6. WebUI 显示“前往绅士漫画手动认证”；
7. 用户在可见浏览器中手动登录后点击“完成操作”；
8. 后端再次访问探针验证登录态；
9. 验证成功才保存 Cookie、关闭旧共享浏览器并自动恢复暂停任务；
10. 验证失败返回 409，保留认证窗口，不覆盖 Cookie，也不恢复任务。

普通 `TaskPauseError` 仍保持原语义；只有显式设置 `resumeTask: true` 的人工处理型暂停才会保留并恢复当前任务。

## 交互

任务页在 Gentleman 登录暂停时展示：

- 当前任务仍保留在队首；
- 跳转到“配置 → 站点配置 → 绅士漫画”的操作按钮；
- 登录并保存成功后任务自动恢复，无需重新触发整批订阅。

配置页的 Gentleman 手动认证入口默认打开韩漫分类探针页面。用户从页面登录入口完成登录，再点击“完成操作”。接口返回的结果会明确说明 Cookie 是否保存、暂停任务是否恢复。

## 验收重点

- 无 Cookie 或 Cookie 失效时，韩漫任务不会把匿名搜索空结果记为成功；
- 暂停的当前任务不会丢失，其他队列顺序不变；
- 未完成登录时不能误保存并提示成功；
- 新 Cookie 生效前会销毁旧内存会话；
- 其他网站任务不执行 Gentleman 登录检查；
- 日志和 API 响应不输出 Cookie 名称或值。
